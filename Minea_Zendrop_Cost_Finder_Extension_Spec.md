# Minea → Zendrop Cost Finder Chrome Extension
## Cursor Implementation Specification — MVP

## 1. Goal

Build a Chrome extension that runs on `https://app.minea.com/*`.

When the user is viewing a Minea product page, the extension should:

1. Detect the current Minea product.
2. Extract the **visible product name** (Product Details Title, then `document.title`) — never Minea’s generic `og:title` slogan.
3. Search Zendrop’s product endpoint with that name using the user's already-authenticated Zendrop web session.
4. Parse the returned object’s `.data` array.
5. Rank every candidate and inject an in-page **Zendrop matches** section after Product Details.
6. Show a scrollable list of all matches with image, cost, and confidence; visually emphasize the top 3.
7. Open **that Zendrop product’s detail page** (`https://app.zendrop.com/product/{id}`), not a search URL.
8. Never ask the user to paste an auth token.

The user will already be logged into Zendrop in the same Chrome profile.

### Critical security rule

The user previously copied a Zendrop Bearer token into a chat. **Do not hard-code, store, log, transmit, or commit that token.** The extension must rely on the browser's existing Zendrop session/cookies.

If authentication stops working, show `Zendrop session unavailable — open Zendrop and log in` rather than requesting a token.

```text
Minea product page
        ↓
Extract visible Title / document.title
        ↓
GET /api/product?page=1&search=<visible-name>
        ↓
Parse response.data
        ↓

        ↓
Inject card after Product Details
        ↓
User sees a ranked list with images + costs
Top 3 emphasized; remaining rows scrollable
Open product → https://app.zendrop.com/product/{id}
```

MVP does NOT need to import products, create stores, place orders, or automate fulfillment.

This is only a **research/pricing bridge**.

# 3. Example data observed from the supplied Zendrop response

Products are **not** a top-level array. The endpoint returns an object whose **`.data`** field is the product list:

```json
{
  "data": [
    {
      "id": 101,
      "name": "Acacia Teak Wood Long-Handled Cooking Spatula Set – Perfect for Mixing & Serving in Style!",
      "supplier_id": 9,
      "base_cost_price": 0.65,
      "display_price": 0.75,
      "featured_image_url": "https://file.zendrop.com/products/b5/0b/316759c6443296452ed913c92936.png",
      "metrics": { "cost": 0.65 }
    },
    {
      "id": 202,
      "name": "7-Piece Wooden Kitchen Utensil Set",
      "base_cost_price": 2.98,
      "display_price": 3.43
    }
  ]
}
```

Useful fields include:

- `name`
- `id` (numeric Zendrop product id; used to open `https://app.zendrop.com/product/{id}`)
- `supplier_id`
- `base_cost_price`
- `display_price`
- `featured_image_url` / `product_image` / `images`
- `metrics.cost`
- optional `url` / `permalink` / `product_url`

Zendrop images are typically hosted at:

```text
https://file.zendrop.com/products/<aa>/<bb>/<hash>.png
```

The parser must read `response.data`, skip malformed rows, and still tolerate a raw array if the shape ever changes.

The extension must prefer the actual `base_cost_price` as the product-cost field when available.

# 4. Zendrop endpoint

The user observed this authenticated request in their own browser:

```text
GET https://app.zendrop.com/api/product?page=1&search=<URL_ENCODED_QUERY>
```

The request was authenticated with the user's existing Zendrop session.

## IMPORTANT

Do NOT put a Bearer token in:

- source code
- manifest
- `.env`
- localStorage
- chrome.storage
- Git
- logs
- UI
- network payloads generated by the extension

Use the browser session.

Preferred implementation:

```text
Minea content script
        ↓ chrome.runtime.sendMessage
background/service worker
        ↓ fetch(..., { credentials: "include" })
Zendrop API
```

The service worker should perform the cross-origin request.

Do not make the Minea content script directly own Zendrop authentication.

# 7. Minea product detection

The supplied Minea page has:

```html
<title>7-Piece Acacia Wood Utensil Set</title>
<meta property="og:title" content="Minea | Find your winning product in 3 clicks.">
```

`og:title` (and twitter title) is a **site slogan**, not the product. `document.title` and the Product Details **Title** row are the real name.

Implement multiple extraction strategies because Minea is a React/Next.js application and DOM structure may change.

Priority:

### Strategy A — Product Details Title row (preferred)

In the Product Details card, the row labeled `Title` holds the visible product name.

### Strategy B — document.title

Read `document.title` after stripping a `| Minea` suffix. Reject generic slogans (`Minea | Find your winning product in 3 clicks.`, exact titles like `Minea`, `Dashboard`, `Products`).

### Strategy C — Next.js data / JSON-LD

Inspect available Next.js page data or JSON-LD if it yields a product-like name.

### Strategy D — visible product heading

Find an H1/product title only if it is not UI chrome (`Shop Details`, `Ads for this product`, `Product Details`, `Find suppliers`).

### Strategy E — product images

Collect candidate images from:

```text
img[alt="product image"]
img[src]
img[srcset]
```

Exclude:

- Minea logos
- avatars
- icons
- UI assets
- tracking pixels
- generic `og:image` / `/_next/static/media/thumbnail...` marketing images

Prefer the largest product-looking image.

Do NOT depend on one brittle CSS selector. Never search Zendrop with the generic og:title slogan.

# 8. Detecting whether this is a product page

The content script should only activate the main UI when a product can be identified.

Suggested heuristics:

```text
URL is /en/products/:id/details (or otherwise indicates product detail)
OR
document.title contains a product name (not a Minea slogan)
OR
visible Product Details Title + product image exists
```

If detection fails:

Show nothing.

Do not poll the page aggressively.

Use:

- initial scan
- MutationObserver with debouncing
- URL-change detection for SPA navigation

# 9. UI placement

Do **not** use a floating top-right overlay as the primary UI.

From the Minea product page, the right column is:

```text
shop header
  → Product Details card
  → [inject Zendrop Cost Finder here]
  → Shop Details card
```

Insert a full-width card immediately after the Product Details card and before Shop Details, inside the right-column flex stack (`div.flex.min-w-0.flex-1.flex-col.gap-4`).

Fallbacks: end of that column, then the main product layout. Remount after SPA navigation because React replaces the DOM.

Keep the UI visually consistent with Minea without copying Minea's proprietary styles. Use Shadow DOM for isolation. The host must be in document flow (`position: static`, `width: 100%`). Not draggable.

The card should be:

- unobtrusive
- responsive
- dark/light-mode friendly
- dismissible

Example:

```text
┌─ Zendrop Cost Finder ─────────────────────────┐
│ Minea: 7-Piece Acacia Wood Utensil Set         │
│ Ranked Zendrop matches · N results             │
│                                                │

│ │        [Open product]                      │ │
│ └────────────────────────────────────────────┘ │
│ remaining ranked rows (scrollable)             │

```

# 10. Search behavior

Initial query:

```text
search = encodeURIComponent(mineaProductName)
page = 1
```

Example:

```text
7-Piece Acacia Wood Utensil Set
```

becomes:

```text
https://app.zendrop.com/api/product?page=1&search=7-Piece%20Acacia%20Wood%20Utensil%20Set
```

Use:

```ts
fetch(url, {
  method: "GET",
  credentials: "include",
  headers: {
    "Accept": "application/json, text/plain, */*"
  }
})
```

Do NOT manually set:

```text
Authorization: Bearer ...
```

Do NOT copy browser DevTools request headers wholesale.

Only send headers necessary for the request to work.

# 11. Authentication behavior

The extension should rely on the user's Zendrop browser session.

Flow:

```text
request Zendrop
       ↓
200
       ↓
parse results
```

If:

```text
401 / 403
```

return:

```json
{
  "authenticated": false,
  "error": "ZENDROP_AUTH_REQUIRED"
}
```

UI:

```text
Zendrop login required.

Open Zendrop in another tab, log in, then click Refresh.
```

The extension should NOT ask for credentials.

It should NOT store Zendrop credentials.

# 12. Matching algorithm

The first MVP should be **keyword matching**, not AI.

Zendrop search already gives us product candidates.

Rank candidates using:

### Title similarity

Normalize:

- lowercase
- punctuation
- stop words
- singular/plural where practical

Calculate token overlap.

### Important token weighting

Give more weight to:

- quantity
- material
- product type
- dimensions
- key features

Example:

```text
Minea:
7-Piece Acacia Wood Utensil Set

Zendrop:
7-Piece Wooden Kitchen Utensil Set
```

This should score highly.

# 13. Image matching

Add image matching as a second stage.

MVP:

1. Extract Minea product image.
2. If Zendrop result contains product images, compare images.

Do NOT implement a huge computer-vision model inside the extension.

For MVP use one of:

- perceptual hash
- image embedding through an optional backend
- an external image similarity API later

The first release can operate entirely from title matching.

Architecture should leave an interface:

```ts
interface ProductMatcher {
  match(
    mineaProduct: MineaProduct,
    zendropProducts: ZendropProduct[]
  ): MatchResult[];
}
```

Then later:

```text
TitleMatcher
ImageMatcher
AIProductMatcher
```

can be combined.

# 15. Shipping

IMPORTANT:

The `/api/product` result may not contain the complete shipping cost.

Therefore the extension must NOT calculate:

```text

```

unless shipping is actually known.

UI should distinguish:

```text
Product cost: $2.98
Shipping: Not retrieved
Estimated landed cost: Not available
```

Interface:

```ts
interface ShippingLookup {

    productId: string;

    destinationCountry: string;

}
```

Default destination:


but make it configurable.

# 17. API response handling

Zendrop returns JSON with a product list on **`.data`**.

Build a defensive parser.

Do not assume one exact response shape forever.

Implement:

```ts
parseZendropProducts(response: unknown): ZendropProduct[]
```

Validate fields with runtime validation (Zod preferred).

Example normalized object:

```ts
type ZendropProduct = {
  id: number;
  name: string;
  supplierId?: number;
  baseCostPrice?: number;
  displayPrice?: number;
  featuredImageUrl?: string;
  productImages: string[];
  permalink?: string;
};
```

Prefer `https://file.zendrop.com/...` URLs as `featuredImageUrl` when present.

Keep raw payloads only in memory for debugging.

Do NOT persist sensitive API response data unnecessarily.

# 18. Caching

Cache search results temporarily.

Key:

```text
zendrop-search:<normalized-query>
```

TTL:

```text
5–15 minutes
```

This prevents repeatedly hammering Zendrop while navigating around Minea.

Do not cache authentication credentials.

---

# 19. Rate limiting

Implement:

```text
minimum 500–1000ms between automatic searches
```

and deduplicate identical searches.

Do not continuously poll Zendrop.

Only search when:

- product changes
- user clicks Refresh
- cached result expires

# 20. Error states

Support:

### No Minea product detected

```text
Could not identify this Minea product.
```

### Zendrop login

```text
Zendrop session unavailable.
Log in to Zendrop and refresh.
```

### No results

```text
No Zendrop products found.
Try searching manually in Zendrop.
```

### Multiple matches

Show **all** ranked results in one vertically scrollable list. Emphasize the top 3 (larger thumbnail, TOP 1/2/3 badge, cost + display price + confidence). Rows 4+ use the same layout at a denser size.

Each row shows image, name, product cost, display price if distinct, match confidence, and **Open product** → `https://app.zendrop.com/product/{id}`.

### API failure

```text
Zendrop search failed.
[Retry]
```

# 21. Open in Zendrop

Each match row’s image, name, and **Open product** control must open **that product’s Zendrop detail page**, not a catalog search:

```text
https://app.zendrop.com/product/{id}
```

Example: product id `202` → `https://app.zendrop.com/product/202`.

Prefer an API permalink (`url`, `permalink`, `product_url`) only if it is already `https://app.zendrop.com/product/<digits>`. Otherwise build the URL from the numeric `id` returned in `data[]`.

Keep a separate **Search Zendrop** action for:

```text
https://app.zendrop.com/product?page=1&search=<query>
```

The popup Open button opens the **best match product page**. Empty/auth states may open the Zendrop catalog or login because there is no product id yet.

# 29. Important implementation note about authentication

The user explicitly wants the extension to work while they are already logged into Zendrop.

Implement authenticated requests using the browser session:

```ts
fetch("https://app.zendrop.com/api/product?page=1&search=...", {
  credentials: "include",
  headers: {
    accept: "application/json, text/plain, */*"
  }
});
```

If Chrome blocks the request due to extension/network restrictions, do NOT ask the user for their token.

Instead, investigate the proper MV3 architecture using the service worker + host permissions and document the exact limitation.

The extension must never bypass authentication or defeat an access control mechanism. It should only use the user's existing authenticated browser session.
